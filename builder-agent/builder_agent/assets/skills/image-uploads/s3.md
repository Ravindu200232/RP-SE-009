# Amazon S3, and anything S3-compatible

Read this only when the S3 bucket option was chosen. SKILL.md still governs
that the file and its record are written together; this is the bucket's own
part.

`STORAGE_BUCKET`, `STORAGE_REGION`, `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`
and optionally `STORAGE_ENDPOINT` and `STORAGE_PUBLIC_URL` are in `.env.local`.

The same code serves Cloudflare R2, DigitalOcean Spaces, Wasabi and Backblaze
B2. They differ only in the endpoint, and R2 wants `region: 'auto'`.

```js
const s3 = new S3Client({
  region: process.env.STORAGE_REGION,
  endpoint: process.env.STORAGE_ENDPOINT || undefined,
  forcePathStyle: Boolean(process.env.STORAGE_ENDPOINT),
  credentials: {
    accessKeyId: process.env.STORAGE_ACCESS_KEY,
    secretAccessKey: process.env.STORAGE_SECRET_KEY,
  },
})
```

`forcePathStyle` is what makes a non-Amazon endpoint work. Without it the
client builds a virtual-host URL against a hostname that does not exist, and
the failure is a DNS error rather than anything that mentions storage.

## The file does not go through your server

Upload with a presigned PUT: your server signs a URL and the browser sends the
bytes straight to the bucket. A route that receives the file first pays for the
bandwidth twice and meets the platform's body-size limit on anything large.

```js
const url = await getSignedUrl(s3, new PutObjectCommand({
  Bucket: process.env.STORAGE_BUCKET,
  Key: key,
  ContentType: type,
}), { expiresIn: 60 })
```

Sign for the content type and the key **your server chose**, after checking
both. A presigned URL is permission: whatever is signed is what may be
uploaded, so signing a client-supplied key lets a caller write anywhere in the
bucket. Keep the expiry short.

## Do not make the bucket public to serve a file

Block public access, and serve either through a CDN in front of the bucket
(`STORAGE_PUBLIC_URL`) or through presigned GET URLs. A bucket opened up to
make one image load is how the rest of it leaks.

A bucket policy is not CORS. A browser PUT to a presigned URL needs a CORS rule
allowing `PUT` from the product's origin, or it fails preflight with nothing
useful in the message. Say this in your report: it is set on the bucket, not in
code.

## Delete the object with the record

`DeleteObjectCommand` answers 204 whether or not the object existed, so the
delete is safely idempotent. A record removed without its object leaves a file
nobody can find and nobody stops paying for.

## Testing it

Stub the client. Assert that the signed key comes from the server, that the
expiry is short, that an upload failure leaves no orphan record, and that
deleting a record deletes its object.
